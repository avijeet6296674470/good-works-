# Avijeet Thakur: CONTENT PLAN

Vertical overlay: `agency` (see `reference/verticals/agency.md`). The site is an evidence problem: buyers cannot inspect the work, only the proof it happened. Two audiences, deliberately separated:

- **Recruiters:** the home page `/`. Written by the owner. Not a keyword target.
- **Clients:** keyword-targeted service landing pages. Each is a landing page, one primary keyword, one job.

## Service page flow (the template)
Hero (Hook, one action, enquiry form) → proof strip → what you get → Watch the work → Results → process → FAQ and stack → CTA → other services.

## Rules
- Every claim sits next to its proof or is cut.
- Case studies use the fixed structure: situation, constraint, what I did, result with measurement window, who says so.
- One enquiry path on every page, plus a direct email.
- The next pass runs each service page through `/page-build` and `/bullshit-detector`.
