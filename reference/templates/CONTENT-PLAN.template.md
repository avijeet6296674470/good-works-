# <FILL: BRAND NAME> — CONTENT PLAN

The master plan. Every page's section flow, band treatments, schema blocks and
conversion logic, in one place.

**The build starts here.** `/page-build` reads this plus the page's copy deck and
assembles from them. No stage invents a section that bypasses this plan;
deviations are approved back into it, never around it.

> **Why one plan rather than per-page notes.** Sites drift page by page. Page
> four gets a section page two should have had, page seven repeats page three,
> and nobody notices because nobody reads all seven at once. A single plan makes
> the whole site legible in one sitting, which is the only way the repetition
> shows up.

**One primary keyword per URL.** Two pages competing for one term is
cannibalisation, and it is created here, at planning time, far more often than
it happens by accident later.

**The "owns" column earns its place.** If two rows describe the same job, one of
the pages should not exist. That is easier to see in this table than anywhere
else, and much cheaper to fix here than after both are built.

## Deviating from the plan

A build stage that wants a different section brings it to Onyx, and **an
approved deviation is written back into this file in the same pass.**

A plan that the site has silently outgrown is worse than no plan, because people
still trust it.
